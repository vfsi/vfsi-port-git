VFSI integration
================

This port targets VNFS 0.0.25 through the public `vfsi-c` 0.3.9 package and
VFSI C ABI v3. Fetch and build that release set from crates.io with:

------------
contrib/vfsi/build-vfsi-c
make USE_VFSI=YesPlease \
    VFSI_CFLAGS="-I$PWD/build-vfsi-c/vfsi-c-0.3.9-vnfs-0.0.25/source/include" \
    NO_CURL=YesPlease NO_GETTEXT=YesPlease NO_TCLTK=YesPlease git
------------

The helper verifies the published `vfsi-c` archive checksum, selects the
public VNFS 0.0.25 crate, rejects Git-sourced Cargo dependencies, and builds
the shared library at:

------------
$PWD/build-vfsi-c/vfsi-c-0.3.9-vnfs-0.0.25/target/release/libvfsi_c.so
------------

At runtime, set `VFSI_IMPL` to `nfs` or `dummy` and point `VFSI_LIBRARY` at
that library. The integration is opt-in; a build without `USE_VFSI` retains
Git's ordinary filesystem path.

The published adapter also exposes mount discovery. With `VFSI_IMPL=nfs`
and no explicit host/export/mount overrides, the port inherits the mount's
version, port, and supported authentication rather than guessing AUTH_SYS.
An older adapter without discovery keeps Git's ordinary filesystem path.
Direct access does not share the kernel client's caches.

Loose-object prefetch is optional (`VFSI_PREFETCH_OBJECTS=1`).
`VFSI_PREFETCH_BYTES` bounds retained object payloads (default 64 MiB;
zero disables payload prefetch). Only regular files with valid loose-object
names are selected. Large objects remain on Git's normal read path;
payloads are released after consumption. Directory replay uses per-directory
indexes rather than scanning every cached object for every directory.

The loose-directory snapshot is limited to 200,000 aggregate entries. One
additional entry is probed to distinguish overflow from a complete listing;
overflow discards the snapshot before replaying application callbacks and
uses Git's complete ordinary scan instead of returning truncated results.

Run `VFSI_LIBRARY=/path/to/libvfsi_c.so sh contrib/vfsi/test-port.sh` to
check count-objects and fsck parity with zero, tiny, and normal byte budgets.

Set `VFSI_TRACE=1` to report successful vector listings and distinguish them
from safe fallback. The port's parity script asserts these completion markers;
missing libraries and incompatible adapters must fall back before results are
exposed. Connections and short-lived metadata snapshots have separate lifetimes.

Scoped object identity
----------------------

With the development SDK's optional `vfsi_get_object_idv` export, cached stat
data is refreshed in bounded vectors together with a versioned identity. The
full key includes a process-local backend namespace, both 64-bit filesystem-ID
words, and the file number. Device IDs are assigned from complete namespace/
filesystem pairs without hashing or truncation; the file number supplies
`st_ino`. Hard-link and mount-view aliases within a shared backend namespace
therefore compare equal, while unrelated namespaces with colliding numbers do
not. The projected `st_dev` values are process-local cache keys, not persistent
kernel mount/device numbers.

An adapter lacking scoped identity, returning an invalid layout, or failing an
identity batch keeps Git's ordinary stat/read fallback. ABI v3 and the existing
`vfsi_attrs` layout are unchanged. To test these not-yet-published exports,
build against the development SDK header with `VFSI_CFLAGS=-I/path/to/vnfs/bindings/c/include`
and set `VFSI_INCLUDE` to that directory for `contrib/vfsi/test-port.sh`.
